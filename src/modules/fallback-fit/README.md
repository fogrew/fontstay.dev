# Fallback fitting

Pure math with no parser, DOM or UI dependency. `FitFont` accepts sorted Unicode
scalar code points and corresponding glyph advances in font units. Inputs are
structurally compatible with the metrics format specified in the parsing spike.

`fitFont(target, fallback, weights, policy)` compares weighted advances on the
**intersection** of both fonts' coverage. Each advance is normalized by its own
`unitsPerEm`. `coverage` is the shared positive weight divided by all requested
positive weight; `missingTarget` and `missingFallback` identify omissions. Zero
weights are ignored. Combining marks with zero advances are valid; an entirely
zero-width average or no shared glyphs fails with a typed `FitError`.
Width accumulation normalizes against the largest shared weight independently
of coverage. A coverage ratio below floating-point range rounds to zero without
preventing fitting of the shared subset.

`fitFromAverages(target, targetWidthEm, fallbackWidthEm, policy)` supports existing
aggregate datasets. Both widths must already use the same character distribution
and be expressed in em. It cannot infer glyph coverage from an aggregate.

Results are unrounded ratios: `1` means `100%`. `sizeAdjust` is target width in em
divided by fallback width in em. Each vertical override is the target metric
divided by **target** `unitsPerEm`, then by `sizeAdjust`. Descent uses its absolute
value. Negative line gaps become zero because CSS percentages cannot be negative;
`lineGapClamped` signals that the original line gap cannot be reproduced.

## Vertical metrics

The default `freetype` policy follows FreeType's SFNT selection: flagged typo
metrics first, otherwise hhea; if hhea ascent and descent are both zero, nonzero
typo metrics, then Windows metrics with zero line gap. Explicit `hhea`, `typo` and
`win` policies select that source or fail if missing. `metricsSource` reports the
selection. Zero ascent/descent are allowed; negative ascent is rejected as
unrepresentable by CSS. Descents can use either signed or magnitude convention.

This is an engine policy, not a promise that every browser/OS selects the same
metrics. Audience-specific selection belongs to the browser support integration.
Variable-font inputs represent whichever instance was extracted. Width fitting
uses raw advances, without shaping, kerning, ligatures or contextual substitutions;
rendered-text optimization is a separate plan task.

## System fonts

`systemFonts` lists nine common system fallbacks (Arial, Helvetica, Times New Roman, Georgia, Verdana, Tahoma, Trebuchet MS, Courier New, Segoe UI) with hhea metrics and the Latin-weighted average advance (`xWidthAvg`) from `@capsizecss/metrics` 4.3.0 (MIT), converted to em. They feed `fitFromAverages` when no glyph data for the fallback is available, so the fit is limited to Latin text and uses Capsize's English weighting.

## Frequency profiles

`languageWeights('en' | 'ru')` returns fresh mutable copies. English is the Latin
profile shipped in Capsize unpack 4.0.1, based on 4,999 English Wikinews abstracts.
Russian counts Cyrillic U+0400–04FF and ASCII space, digits and punctuation in
`# text = ` lines of UD Russian GSD's training corpus at commit
`0f34b7362ac3c3facd1d6ff4b876d241bb15793e` (3,850 sentences). Case is preserved.
These are corpus profiles, not universal frequencies for every kind of text.
Custom `GlyphWeight[]` supports other scripts and language distributions.

The Russian derived frequency data retains CC BY-SA 4.0 attribution to Ryan
McDonald, Vitaly Nikolaev and Olga Lyashevskaya; the corpus text is not included.
The English profile is distributed under Capsize's MIT license. See `CREDITS.md`.

## Reference tests

`lib/reference.json` stores unmodified metrics from `@capsizecss/metrics` 4.3.0
and outputs generated by `@capsizecss/core` 4.1.3 `createFontStack`, with `subset:
'latin'` and `fontFaceFormat: 'styleObject'`, for Inter → Arial and Roboto → Arial.
The test compares the aggregate API with these frozen percentages to within
0.00005 percentage points, accounting for Capsize's four-decimal rounding.
This tests aggregate formula parity; it does not claim that a different corpus,
font version or metric policy produces the same measured average.

## `unicode-range`

`lib/unicode-range.ts` compacts code points into sorted, disjoint ranges (lossless),
formats and parses CSS `unicode-range` values (`U+20-7E, U+A0`), counts and
intersects ranges, and reports coverage of named subsets (`SUBSETS`: latin,
latin-ext, vietnamese, cyrillic, cyrillic-ext, greek, greek-ext). The subset
definitions follow the `unicode-range` values served by the Google Fonts CSS API.
